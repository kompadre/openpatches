## 2026-11-07: Tracker phase 3 — editing; the pattern name moves to the margin

**Pattern name in the gap** (user's change to phase 2): the clip's name is no longer drawn in the lanes; it reads **downward in the gap right of the track, under the ✎**, on a strip of the pattern's colour spanning the clip. The lanes keep only a 2px start line, so the clip's first row is free for notes.

**Editing, FT2-style** (`tracker.js`). The grid is focusable; a click places the cursor (and makes the track the active voice). Z-row / Q-row piano by physical key (`e.code`, so any layout), `1` = OFF, Delete/Backspace clears, arrows / PgUp/PgDn / Home/End / Tab move, Numpad ± and the Octave select change octave, Step (0–16) advances the cursor after each entry. Handled keys stop propagation, so the Section's Delete and the roll's shortcuts don't fire while the tracker has focus. Each note is heard on its track's voice as it goes in. **Typing where the track has no clip refuses** with a message pointing at Section and the ✎. The active track shows **one spare sub-lane** when expanded, so a chord is typed a note at a time. Compact tracks edit lane 0.

**Debounced commit.** An edit changes the pattern object at once (the tracker redraws — every placement follows — and the transport re-snapshots, so it is heard) and marks the pattern dirty; the commit — **`relane(p, { fresh: true })`** (lanes repacked to the minimum, low to high) and `touchPattern(…, 'tracker')`, which the roll, Section and autosave hear — waits for **3 s of quiet**, so lanes never reshuffle under the cursor mid-entry. Leaving the tab, a foreign edit, or `pagehide` commits at once.

**Growing patterns.** Dragging a note's start cell up/down moves it within its pattern; **past the end, the pattern gains the bars it needs** and the note lands there. That and the ✎'s `+ Bar` both check **`growBlocker`** first: a pattern placed (in repeats) right above another clip in any section cannot grow into it — refused with a message naming the section. New model helpers: `growBlocker`, `measuresFor`, `moveNote`, `relane({fresh})`.

**Fixed while testing:** focusing the canvas on click scrolled it into view and tucked rows 00–01 under the sticky heads; now `focus({ preventScroll: true })` (e2e fails without it: scrolled 26px).

Tests: `tracker-model` +5 (fresh relane packs and orders, `measuresFor`, `moveNote`, `growBlocker` incl. cut clips), `tracker-view` +8 (FT2 entry with audition and step, OFF/Delete, refusal outside a clip without stepping, spare-lane chord, one session event on commit with lanes packed, leaving the tab commits, drag-past-end adds a bar, blocked growth); e2e `tracker` +3 (real keyboard entry + refusal, keys don't leak to Section's Delete with a clip selected, click doesn't scroll). 1083 unit, 114 e2e.

## 2026-11-07: Tracker phase 1 — lanes on notes, the pure tracker model

**The plan** (agreed with the user, recorded in TODO.md › Tracker): a Tracker tab that is the Section editor on steroids — rows are the section's sixteenths, columns the 8 tracks, each split into 1–4 monophonic sub-lanes; clips shown in their pattern's colour with a name header; note-on/off only; FT2 keys; mobile later; the Section pane outlines the tracker's viewport.

**Model.** `note.lane` (1–3; **omitted for 0**, so plain patterns store exactly what they did) and `track.lanes` (**omitted for 1**), both through the existing factories; `MAX_LANES = 4`. No schema bump: an older reader drops the fields, which is a loss of layout, not a misreading.

**`tracker-model.js`** (pure). `deriveLanes` spreads notes over lanes in time order, honouring a stored lane while it is free (so notes do not hop), else the lowest free one; past four the **oldest sounding note is stolen** and reported in `stolenAt` for the view to mark — the model keeps its full length. `applyLanes`/`relane` store a derivation. `expandTrack` lays out a track of the section: clip blocks, and every note of every repeat at its absolute column with its lane, its cut end (clip end, steal) and whether an OFF shows (not at the pattern or clip end, not before a legato note, not on a steal). `locate` maps a row into the clip's pattern. Edits — `putNote` (over silence: holds to the lane's next note; inside a held note: cuts it and inherits its OFF), `putOff` (refused over silence: not storable), `clearCell` (a cleared note gives its time back to the note it cut; a cleared OFF holds on) — freeze the visible derivation first, so the notes around an edit keep their lanes. The mapping to `{midi,start,dur}` is exact both ways.

Tests: `tracker-model` (30). 1061 unit, 107 e2e.

## 2026-11-07: Guided bank send for the volcas; volca fm2 as its own profile

**The volcas take no bulk dump.** Tested on the user's volca fm mk2: a 4104-byte bank dump never lands — either the CPU cannot drain it at wire speed or it is simply not implemented (the manual's MIDI chart does not list it). So `bankSend` grew a `strategy` field (`'bulk'` | `'guided'`) and `sendBankToDevice` routes guided profiles to **`sendBankGuided`**: each voice is sent to the edit buffer in turn (`sendVoiceToEditBuffer` with a new `force` option — the dedupe cache is a guess about hardware the user has been saving and knob-turning on between steps), and a modal walks the user through saving it on the device: intro (the Start click is the permission gesture) → per-voice step with name, `Voice n of N`, Resend on failure → Next/Done, Cancel anywhere, the log saying how far it got. No backup leg and no overwrite warning: nothing changes on the device except what the user writes there.

**`volcafm2` is a separate profile** (and `volca fm2` / `mk2` / `mkII` port names detect as it, ordered before the plain `volcafm` rule it also matches): 6-voice where the original is 3 (the old profile wrongly said 6 — fixed), velocity-sensitive where the original ignores it, 64 program slots (`programCount` is now "at least 32"). Both volcas are guided, receive-only, no memory protect.

## 2026-11-07: Import project on Android Chrome routed the file to the WAV probe

**Fixed: on Android, Import Project… answered "not a valid WAV file".** Android's download manager renames a downloaded file whose extension doesn't match its MIME type, so the exported `name.opproj` (a Blob typed `application/json`) lands on the phone as `name.opproj.json`. The shared file input routed purely by extension — `.opproj` → project, `.syx` → syx, everything else → the WAV probe — so the renamed project went to `/api/probe` and the server refused it. The rename is deterministic, so the double extension became the discriminator and then the canonical name (both decided with the user): **exports are `name.opproj.json` on every platform** — Desktop, Android or Amiga — via `FILE_SUFFIX` in `project-io.js`, so the name no longer mutates in transit. Routing recognises `.opproj.json` and the bare `.opproj` older exports carry, while a bare `.json` — which could be anything — routes nowhere by extension. The input also remembers which menu option opened the picker (`pickKind`); a recognised extension (project, `.syx`, `.wav`) still wins, the remembered intent decides only when the extension says nothing. The project pickers accept `.opproj,.json,application/json` (accept can't say "double extension"; it only governs what the picker shows) so Android's picker shows the file at all. Re-export strips either suffix from the project name before appending, so names don't stack extensions. A dismissed picker clears the intent (`cancel` event). `html/app.js`.

Tests: e2e `project` — the export is suggested as `Nocturne.opproj.json` and round-trips as a second project, and the legacy bare `.opproj` name still imports; unit `project-io` pins `exportFilename`. 1005 unit, 105 e2e.

## 2026-11-07: Track effects — delay, drive, compressor, shared reverb, ducker, in WASM

**Decision (with the user):** effects run inside the MSFA WASM, not as eight worklet outputs into a WebAudio graph. `DynamicsCompressorNode` has no sidechain input, so "one track boosted, everybody else ducks" is not expressible natively without main-thread envelope following; and a future piece mixdown renders through the same `render_audio` as live playback, so the export matches what was heard by construction. Drive sits **after** the delay (dirty repeats) and the ducker has one source (user's call).

**Engine** (`external/msfa-wasm/fx.{h,cc}`, `fx_params.h`): `FxRack` runs between the FM engine's per-channel sum and the global ResoFilter in `SynthUnit::GetSamples`. Per channel 0–7: delay → tanh drive (LUT) → block-rate compressor → reverb send; then one shared mono Freeverb and a ducker that follows its source **pre**-effects. Channels 8–15 (the preview on 15) bypass it. The FM engine stays fixed-point; the stage is float at ±1.0 (`FX_IN_SCALE` = 2⁻²⁸ — `audiobuf` is 28-bit full scale there). **Bypass is bit-exact**: with every mask 0 and ducking off the old path runs, tested after every parameter has been set. Silent channels are skipped unless they own a tail. Three exports (`set_fx_enabled/param/global_fx_param`) carry everything; IDs live in `fx_params.h`, mirrored by `html/synth/fx-params.js`, held in step by `test/fx-params-sync.test.js`. `FxRack` is a process-wide global so `reset_engine()` keeps the parameters (as it keeps channel volumes) while `ClearState()` drops the tails. Static allocation throughout.

**Memory:** `channel_outputs_[16][200000]` (12.8 MB) served `get_channel_samples`, which no app code reads; now 8192 samples. Steady-state WASM 30.3 MB → 19.3 MB *with* the delay lines. Shrinking it exposed a latent overrun — `GetSamples` memset the capture to an unclamped `n_samples`, surviving only because the buffer was wider than any render; an 800 ms offline render walked off WASM memory. Fixed; `GetChannelSamples` zero-fills past the window.

**Cost** (Node/V8, this machine): three tracks with everything on **0.83 % of realtime** vs 0.35 % bypassed; eight busy voices 1.30 % vs 0.79 %. The relative figure is large because the FM baseline is small; the effects' cost is roughly fixed while FM scales with voices.

**Model + plumbing:** `track.fx` (four flags + parameters, separate so bypass ≠ reset) and `project.fx`, built from the tables in `fx-params.js` — adding a parameter is one line there. New `clampNum` (no rounding: `clampInt` stored a feedback of 0.35 as 0). `duckSource` is validated not clamped (a stored 99 became slot 7) and `normalizeProject` drops one naming an empty slot. `audio-manager.sendFxSnapshot` is a diff that **switches empty slots off** (a deleted track's delay kept ringing); the worklet takes `fx-param/-global/-enabled/-snapshot`, params before mask. Pushed on `tracks`/`project` events, on worklet `ready`, after emergency stop.

**Mixer UI** (`components/fx-panel.js`): an `FX` button per strip, four letters D O C R lit per effect, opening a `position: fixed` popover of toggles and sliders in `document.body`; `Reverb · Duck` in the header with the boosted track as a select of occupied slots. Slider ticks go live to the engine (`onFxLive` → `setFxParam`), release commits via the session with source `voicebank-fx` (the Mixer redraws letters without re-reading strips; the roll keeps its liveCache). The popover reads its track **by slot on every write**. Header button after the title, not `space-between` — the far end of an eight-strip-wide header was off screen. `window.__opFx` stays as the e2e seam.

Tests: `wasm-fx`, `fx-params-sync`, `track-fx-model`, `fx-snapshot`, `fx-panel`; `e2e/fx.spec.js` incl. the only test that **listens** (AnalyserNode ~1 s after a note: dry 0.000, delay on 0.140, off 0.000). 998 unit, 102 e2e.

## 2026-11-02: The Project — a piece of music, exportable, in six phases

A major version change with **no retro-compatibility**: the pre-Project localStorage world is not read, and existing data is wiped. Planned with the user over several turns; the model is theirs.

**The model.** A **Profile** (localStorage, never exported) holds the project index, the current pointer and the global tag vocabulary. A **Project** is one piece of music, its body in IndexedDB, with two dimensions: **Tracks** on the vertical axis, project-level so every section is played by the same band, and an ordered sequence of **Sections** on the horizontal, each arranging **Patterns** as clips on those tracks. "Section" was chosen over "movement" (ambiguous) and "part" (in most DAWs a per-track event container — i.e. this model's *clip* — so it would point at the wrong level). Tempo is the project's with a **nullable per-section override**, the seam the later rit./accel. automation grows from.

**A track is a Mixer strip is a piano-roll voice is a Section lane** — one record, not four kept in step. This killed a live bug: `song.tracks[].mute` gated whether notes were *scheduled* while the voice bank entry's `.muted` gated the channel's *volume*, neither showed the other, and they could disagree. `audibleTracks()` and `effectiveVolume()` now sit side by side so the scheduler's view and the mixer's cannot drift again. Track volume moved to the engine's own 0–127 scale rather than converting at a boundary — converting at a boundary is how the two flags drifted in the first place.

**Persistence.** The open body is the source of truth in memory, so all ~30 synchronous mutators stay synchronous; a debounced flush writes it back whole through a pluggable backend (IndexedDB in the browser, memory in tests). Autosave is every 30 s and only when dirty, skipped while the transport is busy (the clone costs 1.6–4.3 ms of main-thread time — measured — which would jitter note scheduling, not drop audio), and forced when a take ends.

**No "save your changes?" on exit, and there cannot be.** A page cannot show its own `confirm()` during `beforeunload`, and — measured, not assumed — an IndexedDB transaction opened during unload **does not commit**: both handlers run, the transaction is opened inside them, and the page is torn down first. A reload five seconds after typing a note lost the note. localStorage is the only store that survives there, so the last gasp writes the body to a **crash journal** there and the next boot prefers it when it is newer. If even that exceeds the quota the stale journal is dropped (restoring an older copy would look like success) and a marker is left for the next boot to report.

**The save light.** A square in the footer after the circle (audio) and rhombus (MIDI) — the floppy, and a drive light that blinks green while writing, goes red on failure, and saves when clicked. "Saved 2 minutes ago" counts up beside it. A failed write raises a banner that says not to close the tab, with a Save now button.

**Project management** lives in the File menu — New, Projects… (open/rename/duplicate/delete), Rename — because a project is the whole piece, far more than the Section editor's toolbar, where it used to sit. The open project's name sits in the menu bar and renames on click. The Section editor's name field now names the **section**.

**Export / import**: one `.opproj` JSON file, built and parsed in the page. Sections, patterns, tracks with patch bytes inlined, patches, canvas, and only the tags the project uses. **Not** the WAVs (source material, and the bulk of the workspace) — though jobs travel with their `fileName` and a `sourceMissing` marker, with `statusUrl` cleared so an imported job cannot poll someone else's server. **Not** the profile (a port id means nothing on another machine). Import is always a new project; a newer `schemaVersion` is refused loudly rather than returned missing its unknown parts.

**"Clear History" → "Delete All Data…", and it now does.** The old one removed 5 of ~23 keys — patterns, songs, patch renames and the tag vocabulary all survived a "clear all" — and it **orphaned every imported WAV**, because `canvasStore.clear()` dropped the container records without deleting the blobs they referenced. Now three operations (uploads, bodies, profile) with the WAVs first, and the test asserts storage is *empty* rather than that a list of keys was removed.

**Also client-side now:** `.syx` export built with `syx-builder.js` and saved via a new `download.js`, instead of POSTing to `/api/export-syx` and downloading the result — a round trip to make bytes we were already holding, which also meant the export silently needed the optional inference server. (`/api/play` stays: it is the fallback for a client without WASM.)

**The rename pass.** `song-editor.js` → `section-editor.js`, `createSongEditor` → `createSectionEditor`, `songCol`/`songPos` → `sectionCol`/`sectionPos`, transport mode `'song'` → `'section'`, the tab label, ~40 `.song-*` CSS classes → `.section-*`, the CSS custom properties, the tutorial copy, and every e2e selector. `.midi-section` → `.midi-group` to free the word. **Deleted:** `song-model.js`, `song-session.js`, `sequencer.js` and four test suites.

**Bugs found and fixed along the way**, beyond the two mute systems: the Section lane's slot select assigned a slot directly, so two tracks could share a channel and `normalizeProject()` would drop one *with its clips*, in every section (now `setTrackSlot()` swaps); the piano roll skipped `voicebank`-sourced notifications, correct while the bank kept its own array and wrong once it wrote tracks, leaving a stale track list that created a **second track on an occupied slot**; `normalizeVoiceData` rejected **strings**, but base64 is how patches store `voice_data`, so every assigned voice would have been dropped on save; `clampInt(null, …)` returned **0** rather than the fallback, because `Number(null)` is 0 and finite — a null volume read as silence and a null bpm as the slowest tempo; `updatePattern` replaced the stored record and then re-made its note objects, orphaning the roll's reference and breaking `removeNote`, which finds notes by identity; and idle was signalled by "the write settled *and* the body is clean", so a **failed** write wedged `saving` on forever and Play would have hung permanently.

**Tests:** 845 unit (from 731) and 69 e2e (from 54). New suites for the model, the store, the profile, the session, the section sequencer, the save indicator, project I/O, the Projects dialog, downloads, and `track-identity.test.js` — the standing guard that a lane, a strip and a voice are one track, exercised through all three UIs.

## 2026-11-01: Live tempo changes, and the MIDI panel's two clock settings become one choice

Both halves of the MIDI clock were browser-checked against Reaper. Two bugs came out of it, and the second turned out to be the first.

- **Fixed: a BPM change mid-playback did not move the clock.** The tick worker was told its rate once, in the `start` message, and had no way to change it. Typing a new BPM while the roll ran updated the session — so note *durations* followed it (they read the song on every tick) — but the columns kept arriving at the old rate. **This was also why Reaper would not follow our clock out:** `clockColumn()` re-anchors when `msPerClock` changes, so after a BPM bump it emitted its six ticks at the new tighter spacing while the columns still arrived at the old one. The device saw six fast clocks, a long gap, six fast clocks — unfollowable, and Reaper ignored it. Clock *in* was unaffected and had always worked, because there the tempo is measured from the incoming stream.
- **The worker now retempos a running loop, re-anchoring rather than restarting:** the grid is recomputed from the last tick already emitted, so emitted ticks keep their timing, only pending ones move, and `rawCol` never restarts. On the Atomics path this cannot be a message — the loop blocks in `Atomics.wait` and never returns to its event loop, so a `postMessage` would sit unread until the transport stopped. It travels in the previously-reserved `Int32Array[1]` slot (milli-BPM) with the existing `notify` cutting the current sleep short; the `setTimeout` fallback takes a `{type:'tempo'}` message. In both paths the target is recomputed *after* waking and *before* the precision spin — otherwise a tempo drop gets spun through at the old, shorter interval and the tick fires early. `setTickWorkerTempo()` in app.js, threaded through as the transport's `tempoWorker`; the transport pushes it from `refresh()`, which is already the "the song changed under us" entry point both BPM inputs reach.
- **Fixed: "Send MIDI clock" could sit ticked and send nothing.** `isClockOutEnabled()` is `sendClock && !syncToClock && port`, but the two were independent checkboxes — so leaving *Sync to external clock* on from driving us *from* a DAW made clock-out silently inert, with nothing on screen saying why. They are now **one choice**, enforced in midi-manager rather than the UI: switching either on switches the other off (and becoming a slave stops whatever device was being driven). `initFromStorage()` repairs the both-on state an older build may have persisted — sync wins. The `!syncToClock` guard stays as an invariant, now unreachable through the setters.
- **New: clock out warns when there is no output device.** The one remaining way to tick the box and get nothing.
- **The MIDI panel is restructured by signal direction:** Device type first, then an **Input** section (Input, Input channel, Sync to external clock) and an **Output** section (Output, Device channel, Play notes through, slot map, Send MIDI clock, Output latency, Audition, Panic). Clock now sits with its direction, which is also what makes the two boxes read as the halves of one choice. New `.midi-section` / `.midi-section-title` styles. The send-clock hint now says outright that it is independent of "Play notes through" — the clock goes out with the notes staying internal.
- Tests: `test/midi-clock-in.test.js`'s "a slave does not send clock" asserted the exact trap ("the setting is kept… but it is not acted on") and was replaced by both directions of the new exclusion plus the legacy-storage repair (**734 unit passing**). `e2e/transport.spec.js` gains a tempo-change case measuring the column rate either side of a mid-playback doubling — confirmed to fail on the old behaviour; `e2e/midi.spec.js` gains the exclusion through the real checkboxes, the no-output warning, and clock streaming with **Internal synth only** selected while zero note-ons reach the port (**54 e2e passing**).
- Also: `server.py` took `sys.argv[1] or 8000`, which raises `IndexError` with no argument.

## 2026-10-31: VoiceBank de-flaking — one write path, slot badges, the Mixer tab

The relation between engine patches, the VoiceBank, the playing pattern and the Song editor's tracks was flaky. Root cause was not one bug but an architecture: **four uncoordinated writers** into a bank whose array was `splice`d even though the slot index *is* the synth channel.

- **Fixed: removing a voice silently repointed every track below it.** `removeEntry` (and the drop-dedup path) spliced the entries array, so each entry below shifted channel *and* was recoloured by `reindexColors` — a Song track bound to `slot: 3` started playing slot 4's voice, and the roll's note colours moved under the user. - **Fixed: duplicates could enter the bank.** Both dedup paths compared `string===string` or `Array===Array` and returned false for any mismatched pair, so a `Uint8Array` entry never matched an `Array` one; `addEntryAt`/`insertEntry`/`_setEntries` skipped dedup entirely.

## 2026-10-30: MIDI clock in — following an external device

- **"Sync to external clock"** in the MIDI settings (off by default). With it on, Play and Record only **arm**: the Play button pulses amber, nothing runs, and the device's Start runs us — from the top — at the device's tempo, measured from its clock (the mean of the last quarter note's worth of periods). Its Stop pauses us and leaves us armed, so its next Start or Continue is followed too; Continue resumes from where we were. Our own Stop disarms. **Song Position is ignored**, by decision.
- Realtime bytes (0xF8 and up) are routed to the clock before SysEx and notes — they may legally arrive mid-SysEx, and the note handler drops them anyway. A slave **does not send clock** (it would loop straight back onto the bus), and switching to slave while clocking a device stops that device first.
- The recorder's time base is now the moment the transport actually begins a take, not the moment Rec was pressed, and its column arithmetic uses the transport's effective tempo: under an external clock the two moments can be seconds apart and the tempos differ. (Rec on a stopped transport is a step record; Play then Rec arms a take.) A take into an empty song still starts on the device's Start.
- `test/midi-clock-in.test.js`; verified in a browser with a hand-driven fake input: armed → Start → columns → device Stop (paused, armed) → Continue → our Stop → a later Start ignored. This closes the "basic internal clock sending / syncing with external" item.

## 2026-10-30: MIDI clock out

- **"Send MIDI clock"** in the MIDI settings (off by default): the app's transport drives an external sequencer or drum machine. Start, Stop, and 24 ticks to the quarter note at the song's tempo, from both Play and Record. Starting anywhere but the top sends a Song Position first and Continues from it — a MIDI Song Position counts sixteenths, which is exactly our columns, so a loop starting at bar 2 tells the device so.
- The tick worker wakes once per column (a sixteenth), so each column is scheduled as **six timestamped clocks in one batch** rather than run off a 24-PPQN timer of our own. Their times come from a base anchored at the first column, not from each tick's own arrival: a device reads the gaps as the tempo, so worker jitter would be audible wobble, and a late batch could otherwise be stamped behind the batch before it. The base re-anchors on a tempo change. Measured in a browser against a fake port: 48 clocks in a second at 120 BPM, every gap 20.833 ms.
- Clock goes out through the same path as notes, so it carries the output latency and the device stays in step with what you hear. It is deliberately independent of "Play notes through" — clocking a drum machine while listening to the internal synth is an ordinary thing to want. Panic stops it, which is what a closing tab calls.
- `test/midi-clock.test.js`. The audition checkbox gained a `.midi-audition` class so a panel test stops identifying it as "the first checkbox".

## 2026-10-30: Step record — Rec without Play

- **Rec with the clock stopped arms a step record** instead of starting a take. A key (on screen or MIDI) held for a full second puts a sixteenth on the grid at the step cursor and grows it by one for every further second — the length on the grid when the key comes up is the length kept. **A tap shorter than a second is a sixteenth rest; two such taps within half a second are a quarter rest.** Keys down together are a chord with their own hold times; when the last comes up the cursor moves past the longest note (or the rest), wrapping at the pattern's end. The roll centres vertically on each new note and scrolls sideways only when the cursor leaves the view. Undo works as for a take. The cursor is drawn as the roll's playhead (`setStepCursor`) and the Rec button is lit without the pulse (`.step`).
- Steps go **into the pattern on screen** (the roll's `getEditTarget()`), not through the take's slot-based `mapRecordColumn`: the voice select's record slot and the roll can disagree (opening a clip from the Song tab on a track whose slot holds no patch moves the roll but not the recorder, since `_setActiveSlot` ignores empty slots), and the first browser check saw exactly that — notes landing in another track's pattern or nowhere, with no error. With nothing on screen the note starts a track on the record slot. Step notes carry no `_recordedInSession` guard, so they sound on the first pass of a take that follows.
- **Rec over a running clock is still a live take**, and **Play while a step record is armed converts it into one** (the roll's `onBeforePlay` hook; the mobile Play goes through the same path) — which is now how a take on an empty song begins, since Play alone refuses an empty roll. A clock started elsewhere (the Song tab's Play) ends the step record.
- `test/toolbar-step-record.test.js`; the Rec-from-stopped cases in `toolbar-record-keyboard.test.js` now start playback first.

## 2026-10-29: Song-level play controls; the roll's Play loops the pattern where it sits

## 2026-10-29: Patterns, Tracks and the Song editor

The sequencer is rebuilt around reusable **patterns**. Six phases, one commit each.

- **Model** (`html/components/song-model.js`) — Pattern (a bar or more of notes, monotimbral: notes carry no voice), Track (bound to a voice-bank slot = synth channel = MIDI channel), Clip (a pattern on a track at a bar, with repeats), Song (tracks + clips + bpm + loop). Factories are total, so stored or hand-edited data comes back well-formed. Id-keyed stores, so names are free and two patterns may share one. One clip per track per bar.
- **Migration** — the old flat roll (whose per-note `slot` was the voice) becomes one pattern + track per used slot; legacy saved songs convert the same way, keeping their voice bank. Versioned and idempotent; the legacy keys are never deleted.
- **Sequencer core** (`html/synth/sequencer.js`) — pure: given a song and its patterns, what starts at column N and on which slot. Patterns are snapshotted at compile time (reading one parses localStorage, which must never happen on a tick); mute/solo are read live. Solo beats mute.
- **Pattern editor** — the piano roll now edits one pattern, the active voice's. Other tracks draw as read-only ghosts behind it. `notes` became a binding repointed at the active pattern, which is why the editing layer survived the change untouched.
- **Song editor** (`html/components/song-editor.js`, Song tab) — tracks × bars grid, pattern palette, place/move/repeat/remove clips, per-track voice + mute/solo, song select/name/BPM/loop. Autosaves; model refusals ("Clip overlaps") surface in a status line. A shared `song-session.js` owns the current song so neither editor overwrites the other.
- **Transport** (`html/synth/transport.js`) — one owner of the clock, subscribed to the tick worker exactly once (previously the roll and the toolbar each drove it). Modes: Song (default, and identical to the old behaviour) and Pattern. Drives both playheads and recording; recording still sounds the whole arrangement as a backing.
- **Cleanup** — `song-bar.js` and the legacy `songStore` removed; the voice bank now follows the song on a switch; tutorial and HEARME.tts updated.

Caught in review along the way: recording into an empty song dropped the note; the tutorial was opening the wrong tab after the Song tab shifted the indices; and songs saved through the old song bar after the first migration would have been stranded by its removal.
